4　対策

プレースホルダでは守れない部分

プレースホルダで渡せるのは、「値」だけです。並べ替えの列名（ORDER BY）や、テーブル名を、利用者の指定で変えたいときは、別の対策が必要です。

危険な例

// ユーザーが sort=price や sort=name を指定 db.query(`SELECT * FROM items ORDER BY ${sort}`)

指定された文字列が、そのままSQL文の構造になる。プレースホルダ（?）は使えない。

安全な例：許可リスト（ホワイトリスト）

const allowed = { price: "price", name: "name" }; const col = allowed[sort] ?? "name"; // 許可した列名だけ db.query(`SELECT * FROM items ORDER BY ${col}`)

利用者の入力は「選ぶだけ」にして、SQL文に入る文字列は、アプリが決めたものに限る。

「値」はプレースホルダ。「構造」は許可リスト。

6　AI生成コード

AIが生成したアプリは、なぜ確認が必要か

AIが作ったコードは、動くことが多い一方で、安全でない書き方が含まれる可能性があります。「動く」と「安全」は、別の問題です。

理由 1

動くことが優先されやすい

短く書ける「文字列をつなげる」書き方が、そのまま出力されることがある。

理由 2

学習した古い書き方が混ざる

学習データには、安全でない書き方も含まれるため、そのまま再現されることがある。

理由 3

頼み方で、変わるとは限らない

「安全に」と頼んでも、毎回、正しく直るとは限らない。結果を、人が確認する必要がある。

理由 4

作った人が、気づきにくい

コードを読まずに公開すると、問題があっても気づけない。

AIが書いたコードも、人が確認してから、公開する。
