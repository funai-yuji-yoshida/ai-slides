たとえるなら

知識は豊富だが、あなたの会社のことは何も知らない「超優秀な新人」

得意

要約、分類、文章作成、アイデア出し、翻訳

社内ルール、顧客情報、昨日の会議の内容

あいまいだと

基礎

プロンプト

AIへの指示書。新人への仕事の頼み方と同じです。

結果がぶれる何を基準に、どんな形でまとめるかをAIが推測するため、毎回違う答えになります。
狙いどおりの結果役割・目的・材料・出力形式がそろうと、そのまま使える答えが返ってきます。
役割誰として
目的何のために
材料何を見て
出力どんな形で
問い合わせをまとめて
# 役割
あなたは営業事務の担当者です。
# 目的
今日対応すべき問い合わせを決めたい。
# 材料
添付のCSV（問い合わせ一覧）
# 出力
優先度順の表：会社名／内容／対応期限
Lv1

Markdown

記号で見出しや箇条書きを表す、シンプルな文章の書き方

たとえるなら

Wordの「見出し」「箇条書き」を、記号だけで書いたメモ

  • # 見出し　- 箇条書き　** 強調
  • AIは区切りから「どこに何が書いてあるか」を正確につかめる
  • ChatGPTやGeminiの回答も、実はMarkdownで書かれている

書いたもの

# 定例会議メモ（10/5）
## 決定事項
- 新商品の発売日は **11月15日**
- 価格は据え置き
## 宿題
- 販促案：吉田（10/12まで）

表示されると

決定事項

  • 新商品の発売日は 11月15日
  • 価格は据え置き

宿題

  • 販促案：吉田（10/12まで）
Lv2

JSON

「項目名（キー）：値」のセットで情報を表す、データの書き方

たとえるなら

記入済みの申込書。欄の名前と書かれた内容がセットになっている

  • 項目が固定されるので、AIが読み違えない
  • 「この形で返して」と出力形式の指定にも使える
  • システム同士のやりとりの標準形式（→ API）

申込書の欄をクリックすると、対応する行が光ります

{
  "company": "株式会社A",
  "contact": "吉田",
  "request": "見積もり再送",
  "priority": "高"
}
Lv2

YAML

JSONと同じ情報を、人が読み書きしやすくした書き方

たとえるなら

カッコや記号を減らして、字下げ（インデント）で整理した設定メモ

  • 字下げの深さが「階層」を表す（ずれると意味が変わる）
  • AIエージェントやチャットボットの設定ファイルでよく使う
  • 人が書くならYAML、機械に渡すならJSONが目安

社内チャットボットの設定（同じ内容を切り替え）

bot:
  name: 総務アシスタント
  tone: ていねい
  rules:
    - 社内規程に基づいて回答する
    - 不明なときは総務部へ案内する
{
  "bot": {
    "name": "総務アシスタント",
    "tone": "ていねい",
    "rules": [
      "社内規程に基づいて回答する",
      "不明なときは総務部へ案内する"
    ]
  }
}

Markdown・JSON・YAMLの違い

どれもテキストですが、「誰が読み書きするか」が違います。

Markdown

人間が読みやすい

## 問い合わせ
- 会社：株式会社A
- 優先度：高

使う場面：プロンプト・資料・指示書

JSON

AI・システムが扱いやすい

{
  "company": "株式会社A",
  "priority": "高"
}

使う場面：AIへの入出力・API

YAML

人間が設定を書きやすい

company: 株式会社A
priority: 高

使う場面：AI設定・設定ファイル

JSON＝機械に渡しやすい

YAML＝人間が設定を書きやすい

Lv3

CSV

1行に1件、項目をカンマで区切ったテキストの表

たとえるなら

Excelの表から、色や罫線を取り除いた「中身だけ」

  • 数百〜数万件でも同じルールで扱える
  • Excel・業務システム・AIの間で受け渡ししやすい
  • 集計はAIにコードで計算させ、必ず検算する
日付,会社,内容,優先度

2026-10-02,B商事,納期確認,中
2026-10-03,C工業,資料請求,低
日付会社内容優先度
2026-10-01株式会社A見積もり再送高
2026-10-02B商事納期確認中
2026-10-03C工業資料請求低
Lv3

RDB（リレーショナルデータベース）

複数の表を「共通の番号」でつないで管理する仕組み

たとえるなら

顧客台帳と受注台帳を「顧客番号」でひも付けた帳簿セット

  • 同じ情報を何度も書かないので、修正が1か所で済む
  • CRMや販売管理など、多くの業務システムの中身
  • AIに渡すときは、必要な表をつないで取り出す（→ SQL）

顧客をクリックすると、その顧客の注文がつながります

顧客番号会社名地域
顧客番号でつながる
注文番号顧客番号商品数量

　

Lv4

SQL

データベースから、必要なデータだけを取り出すための言語

たとえるなら

資料室の担当者に渡す「この条件の資料だけ出して」という依頼メモ

  • 全件ではなく、絞り込んでからAIに渡すと精度もコストも改善
  • SQL自体は、日本語で頼めばAIが書いてくれる

やりたいことを選ぶと、SQLと結果が表示されます

知識の一覧

  
それぞれをAI活用のどこで使うかを押さえておきます。

  

   
知識一言でいうとAI活用で何に使う？

   
    
Markdown人間にもAIにも読みやすい文章の書き方プロンプト・資料・指示書

    
JSONデータを機械が扱いやすく整理する形式AIへの入出力・API・構造化データ

    
YAML設定情報を人間にも読みやすく書く形式AI設定・プロンプト・設定ファイル

    
CSV表をデータとして保存する形式Excel／スプレッドシートとの連携

    
RDBデータを表形式で整理して保存する仕組み顧客・商品・売上などの大量データ

    
SQLRDBに「このデータを出して」とお願いする言葉データ検索・集計

    
APIシステム同士がデータを受け渡す窓口AIと他システムの連携

   

 







 

  
迷ったときの使い分け

  
形式選びは「誰が読むか」と「件数」で決まります。

  
    
   
  • 人も読む文章ならMarkdown
    • 
   
  • 項目が決まっているならJSON / YAML
    • 
   
  • 件数が多いならCSV / RDB
    • 
   
  • 一部だけ使うならSQLで絞ってから渡す
    • 
   
  • 毎回の作業を自動化するならAPI連携
    • 
  

  
個人情報や社外秘のデータは、社内ルールで許可された環境以外に入力しないこと。練習にはダミーデータを使います。
